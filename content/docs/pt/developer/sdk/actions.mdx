## Declara ações de backend

O esquema v6 permite que um plugin com componente de backend declare até 64 entradas em `actions`. Cada entrada tem um `id` único, um `label` e uma `description` legíveis, e `scope` com `app` ou `workspace`. O host chama `invoke` com JSON da forma `{"action":"action-id","input":...}`, usando o âmbito explícito de aplicação ou espaço de trabalho de quem chama. As ações continuam sujeitas aos limites da sandbox do componente e às autorizações do plugin. Invocar um pacote que declara ações exige um identificador de ação declarado.

O esquema 9 dá a uma ação um formulário e locais na aplicação. `inputs` lista até 16 campos, cada um com `id`, `label`, `description` opcional, `required` e um `kind`: `text`, `longText`, `number`, `boolean`, `choice` (com `choices`), `language`, `subtitles` ou `json`. O Arrumo mostra o formulário em vez de uma caixa de JSON e envia `input` como um objeto com as chaves dos identificadores das entradas. Uma entrada `subtitles` deixa o criador escolher uma faixa de legendas do vídeo em vista, abrir um ficheiro SRT ou colar um, e envia o texto SRT. `placements` lista onde a ação é oferecida além das Definições: `draft` (junto de um rascunho), `generation` (na página de geração de um vídeo) e `completed-video` (num vídeo terminado, incluindo o menu de contexto). `translations.<lang>.actions.<id>.inputs.<input>` traduz o `label`, a `description` e as `choices` de uma entrada.

```json
{
  "id": "translate-subtitles",
  "label": "Translate subtitles",
  "description": "…",
  "scope": "workspace",
  "inputs": [
    {
      "id": "subtitles",
      "label": "Subtitles",
      "kind": "subtitles",
      "required": true
    },
    { "id": "language", "label": "Into", "kind": "language", "required": true }
  ],
  "placements": ["completed-video"]
}
```

### Executa uma ação sozinha (hooks)

Uma ação de espaço de trabalho do esquema 9 também pode declarar `hooks`, para correr sem ninguém abrir o formulário. Há três eventos, com no máximo um hook cada: `video-completed` dispara uma vez por vídeo terminado, depois de o Arrumo verificar os ficheiros de entrega; `generation-failed` dispara uma vez por tentativa de geração falhada; e `publish-date-reached` dispara uma vez por saída terminada na data que o criador lhe atribuiu no calendário. Cada hook indica em `enabledBy` uma definição booleana do mesmo plugin, e só corre enquanto essa definição for `true` para o espaço de trabalho, por isso nada acontece até o criador a ativar. O Arrumo mostra o hook junto do formulário da ação.

```json
"settings": [{"id": "auto-upload", "label": "Upload finished videos", "description": "…",
              "kind": "boolean", "scope": "workspace", "required": false}],
"actions": [{"id": "upload", "label": "Upload", "description": "…", "scope": "workspace",
             "hooks": [{"event": "video-completed", "enabledBy": "auto-upload"}]}]
```

Uma execução por hook é uma tarefa de ação normal, listada com as outras em **Ações de plugins**. A entrada é o evento em vez dos valores do formulário:

```json
{
  "event": "video-completed",
  "video": {
    "runId": 3,
    "title": "Launch",
    "profile": "Shorts",
    "outputs": [
      {
        "formatId": 5,
        "format": "Landscape",
        "durationSeconds": 12.5,
        "scheduledFor": "2026-11-20"
      }
    ],
    "texts": [{ "kind": "description", "format_id": null, "text": "…" }]
  }
}
```

`texts` contém o título, a descrição e as etiquetas aprovados; fica vazio quando a entrada ultrapassaria o limite de 64 KiB para plugins. O identificador da tarefa deriva do evento, do vídeo (e da tentativa) e da ação, por isso um evento repetido nunca executa um hook duas vezes.

Um hook `generation-failed` recebe a execução, a tentativa e o problema registado pelo Arrumo (até 2000 caracteres):

```json
{
  "event": "generation-failed",
  "video": {
    "runId": 3,
    "title": "Launch",
    "profile": "Shorts",
    "attempt": 1,
    "problem": "The agent stopped before rendering."
  }
}
```

Um hook `publish-date-reached` recebe a forma de `video-completed` com `"event": "publish-date-reached"` e só a saída cuja data chegou. O Arrumo verifica de poucos em poucos minutos enquanto está aberto; uma data com até sete dias continua a contar, por isso um dia em que a aplicação esteve fechada não se perde. Cada saída e data executa o hook uma vez, mesmo que a data volte a ser movida para esse dia.

O criador pode saltar um hook ativo para um vídeo concreto ao gerá-lo.

O [exemplo de ações](https://github.com/aidevs-pt/arrumo-plugin-sdk/blob/main/examples/actions/manifest.json) usa o mesmo componente echo compilado do exemplo de backend. Compila `examples/component/echo.wat` para `examples/actions/echo.wasm`, empacota com `--include echo.wasm` e instala o ZIP. Usa `plugin-actions` para descobrir as ações e envia JSON pela entrada padrão para `invoke-plugin-action action-echo echo app`.
