## Paquetes ZIP locales

Coloca un único `manifest.json` del SDK en la raíz del ZIP. Se admiten manifiestos almacenados y comprimidos con Deflate. El editor limita un paquete a 16 MiB y 512 entradas, y su manifiesto a 64 KiB. Usa nombres de entrada relativos en UTF-8 con barras normales. Evita nombres duplicados, incluidos los que solo se diferencian en mayúsculas. Se rechazan las entradas cifradas y los enlaces simbólicos.

Arrumo guarda el ZIP original y su digest SHA-256. El digest identifica los bytes importados para compararlos con la suma de comprobación de una publicación. Registrar el paquete deja su contenido inerte. Ejecutar una capacidad requiere un adaptador de confianza aparte.

### Compila un paquete

Con Python 3.11 o posterior y `jsonschema` instalado, ejecuta:

```console
python /path/to/plugin-sdk/tools/package_plugin.py /path/to/plugin plugin.zip --include LICENSE --include README.md
```

La herramienta valida e incluye automáticamente el manifiesto de la raíz. Pasa cada archivo adicional explícitamente con `--include`. Los mismos archivos producen bytes de ZIP idénticos sin importar el orden de los argumentos ni las marcas de tiempo del sistema de archivos. La salida es un archivo nuevo, y la herramienta imprime el identificador del complemento, la versión del esquema del manifiesto, el tamaño en bytes y el SHA-256. Usa ese digest al preparar el registro de la publicación.

## Paquetes con código

La versión 3 del esquema de manifiesto añade una sección `code` opcional. Incluye un componente de backend WebAssembly en `backend.component`, documentos HTML de entrada propios en `frontend`, o ambos. Cada punto de entrada debe ser un archivo no vacío del ZIP. Incluye explícitamente al empaquetar cualquier JavaScript, estilo o recurso incluido.

```json
{
  "backend": { "component": "backend/plugin.wasm" },
  "frontend": [
    {
      "id": "example-panel",
      "title": "Example panel",
      "document": "frontend/index.html",
      "placement": "workspace"
    }
  ]
}
```

Usa identificadores de superficie únicos. Las ubicaciones admitidas son `settings`, `workspace` y `completed_video`. El host valida la declaración, comprueba que el ZIP contenga los puntos de entrada y conserva el paquete. Los componentes de backend instalados se pueden invocar explícitamente mediante Arrumo. Las superficies de interfaz instaladas se renderizan en marcos aislados. Las concesiones de capacidades del host se declaran y aplican por separado.

### Invoca un backend

Implementa el [mundo WIT de backend](https://github.com/aidevs-pt/arrumo-plugin-sdk/blob/main/wit/plugin.wit). La exportación `invoke` recibe texto JSON en UTF-8 y devuelve texto JSON en UTF-8. El host instancia un componente nuevo sin importaciones del host ni WASI. Así, un componente solo recibe la entrada que aporta quien lo llama. El host limita el tamaño del componente a 4 MiB, la entrada y la salida a 64 KiB cada una, y aplica límites de memoria y de combustible.

El [ejemplo echo](https://github.com/aidevs-pt/arrumo-plugin-sdk/tree/main/examples/component) incluye el manifiesto y un componente escrito a mano en formato de texto WebAssembly. Compílalo con `wasm-tools parse examples/component/echo.wat -o examples/component/echo.wasm` y después empaqueta el directorio del ejemplo con `--include echo.wasm`. Tras instalarlo, pasa JSON por la entrada estándar al comando `invoke-plugin component-echo` de la CLI del editor.

### Lee el contexto del espacio de trabajo compartido explícitamente

Con la versión 4 del esquema de manifiesto, un backend puede declarar `"permissions": ["workspace-context-read"]` en `code.backend` e implementar el mundo WIT `workspace-plugin`. Instalarlo no concede ningún permiso. Un operador puede conceder este permiso a un paquete instalado concreto en un espacio de trabajo concreto.

Invoca el complemento con el identificador de ese espacio de trabajo. El host enlaza `read-workspace-context` solo cuando la concesión coincide con el paquete actual. La función devuelve el contexto del espacio de trabajo como cadena JSON o `null`, y se puede llamar una vez por invocación. La concesión se evalúa al empezar la invocación. Actualizar o quitar el paquete retira la concesión para las llamadas siguientes.

### Renderiza un panel de interfaz

Cada punto de entrada de interfaz debe ser un documento HTML autónomo en UTF-8 de 512 KiB como máximo. Incluye su JavaScript y sus estilos en línea y usa URL de datos para imágenes o fuentes incrustadas. La aplicación de escritorio carga el documento desde un protocolo local dedicado en un marco aislado con origen opaco. El panel no tiene un puente directo a comandos nativos. Los datos del espacio de trabajo solo están disponibles mediante un permiso declarado y una concesión explícita. La política de contenido limita la carga de recursos al documento y sus recursos en línea.

Empaqueta el [ejemplo de contador de interfaz](https://github.com/aidevs-pt/arrumo-plugin-sdk/tree/main/examples/frontend) con `--include index.html`. Tras instalar el ZIP, abre el panel en **Paneles de complementos**, en los Ajustes de escritorio.

### Lee el contexto desde un panel de interfaz

En el esquema v5, un panel `workspace` o `completed_video` puede declarar `"permissions": ["workspace-context-read"]`. El operador debe conceder acceso al paquete instalado en el espacio de trabajo actual. El host elige el espacio de trabajo.

Envía un mensaje a `parent` con `type: "arrumo:workspace-context"` y `nonce: location.hash.slice(1)`. Transfiere un puerto de `MessageChannel` con la petición. El host responde una vez por apertura del panel en ese puerto con `{ok: true, context: string | null}` o `{ok: false, error: "context_unavailable"}`. La revisión del paquete, la declaración del panel y la concesión del espacio de trabajo se comprueban en el momento de la petición. Consulta el [ejemplo de panel de espacio de trabajo](https://github.com/aidevs-pt/arrumo-plugin-sdk/tree/main/examples/workspace-panel). Muestra el contexto devuelto como texto.

## Prepara archivos de paquetes revisados

Usa `tools/stage_plugin_package.py` para copiar archivos concretos de un ZIP instalado o incluido exportado por el editor. Pasa el digest revisado en el catálogo y un directorio de destino nuevo.

```sh
python3 tools/stage_plugin_package.py package.zip /path/to/new-stage \
  --sha256 <reviewed-digest> --include tools/worker.py
```

Repite `--include` para cada dependencia que necesite el worker. La herramienta verifica el ZIP exacto, comprueba las rutas y los tipos de las entradas, aplica los límites de tamaño comprimido y descomprimido, y publica el directorio cuando se han escrito los archivos elegidos. La ejecución corresponde al entorno configurado de quien lo usa.

## Ejecuta un worker multimedia revisado en Linux

`tools/run_media_package.py` ejecuta un punto de entrada Python revisado con el mismo sandbox de Bubblewrap que el renderizador de movimiento. El código del paquete es de solo lectura en `/input`. Un directorio de entrada dedicado es de solo lectura en `/media`, y el worker escribe en `/output`. El proceso usa un entorno vacío y un espacio de nombres de red separado. Pasa solo los medios que necesita el trabajo.

```sh
python3 tools/run_media_package.py package.zip --sha256 <reviewed-digest> \
  --inputs /path/to/media --output /path/to/new-output \
  --entrypoint tools/worker.py --include tools/helper.py
```

El worker escribe `/output/result.json` como `{"file":"artifact.mp4"}` o nombra un WAV del mismo directorio. El host debe validar los medios antes de importarlos. Este ejecutor necesita en Linux Bubblewrap, Python y las herramientas multimedia que use el worker. El comando admitido usa un tiempo límite de reloj, un espacio temporal acotado y un límite de salida por archivo.
