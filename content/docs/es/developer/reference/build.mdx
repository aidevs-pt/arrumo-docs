## Desarrollo de escritorio

Instala los [requisitos previos de Tauri](https://v2.tauri.app/start/prerequisites/), Node y la versión de pnpm indicada en `package.json`.

```sh
pnpm install --frozen-lockfile
pnpm tauri dev
```

Mientras la aplicación arranca, una pantalla cobalto anima el logotipo de la cara; se desvanece cuando el idioma y los espacios de trabajo han cargado, y queda quieta si el movimiento reducido está activado. Define `ARRUMO_NO_SPLASH=1` (por ejemplo, `ARRUMO_NO_SPLASH=1 pnpm tauri dev`) para omitirla al depurar.

La primera pantalla de escritorio crea y lista espacios de trabajo. Usa el idioma del sistema cuando es inglés, español o portugués, con inglés como alternativa. La aplicación guarda `workspaces.sqlite` en el directorio local de datos de aplicación de cada plataforma. El mismo almacén de espacios de trabajo alimenta la CLI.

`pnpm tauri build --debug --no-bundle` compila un ejecutable nativo a partir de la interfaz estática. Los instaladores y la firma se gestionan aparte.

## Complementos incluidos

En la estructura del espacio de trabajo de Arrumo, la compilación lee el archivo hermano `plugin-registry/catalog.json` y carga las entradas marcadas como `default` desde los checkouts hermanos `plugins/<id>`. Los checkouts pueden ser enlaces simbólicos. Define `ARRUMO_PLUGIN_REGISTRY` y `ARRUMO_PLUGIN_SOURCE_ROOT` para usar otro archivo de registro u otra ubicación de checkouts. La compilación incrusta los artefactos seleccionados de esas fuentes sin guardar copias en el repositorio del editor.

En compilaciones locales de depuración, coloca un `plugin.zip` generado con el SDK en el checkout hermano del complemento seleccionado. El host valida el ZIP y exige que su manifiesto coincida con el checkout antes de exponer sus acciones o superficies de interfaz. El contexto del espacio de trabajo sigue necesitando una concesión para ese digest de paquete.

En compilaciones de publicación desde el registro, define `ARRUMO_PLUGIN_RELEASE_ROOT` con un directorio que contenga los archivos `<id>.zip` preparados. Cada ZIP preparado debe coincidir exactamente con un SHA-256 de publicación del registro seleccionado, y su manifiesto debe coincidir con el checkout correspondiente. El catálogo incluido conserva la versión publicada, el repositorio de origen y la URL del paquete. Las compilaciones de publicación solo incrustan ZIP ejecutables y descriptores de adaptadores de proveedores desde esta ruta de preparación verificada. Las compilaciones de depuración sin preparación pueden usar los descriptores de los checkouts hermanos. Un complemento predeterminado sin ZIP preparado no tiene adaptador de proveedor incluido en las compilaciones de publicación.

Usa `export-plugin-package <plugin-id> <sha256> <new-zip>` para copiar un paquete incluido o instalado desde el catálogo local. El editor recalcula el digest y se niega a sobrescribir un archivo existente. Obtén el digest esperado de la entrada del paquete que revisaste en `plugin-catalog`.

Usa `ARRUMO_CORE_ONLY=1` para verificar el host de forma aislada sin acceso a los checkouts privados. Esa compilación empieza con un catálogo predeterminado vacío.

## Línea de comandos

Desde este repositorio, usa Cargo para crear y listar espacios de trabajo en una base de datos SQLite local.

```sh
cargo run --locked -- ./workspaces.sqlite create "My studio"
cargo run --locked -- ./workspaces.sqlite list
```

Los comandos imprimen JSON. La base de datos se conserva entre ejecuciones. Ejecuta las pruebas del backend con `cargo test --locked`.

## Traducciones de la interfaz

Copia `locales/en.json` a un archivo nuevo, como `locales/fr.json`, y traduce los valores. Mantén las mismas claves y conserva las sustituciones como `{name}`. La compilación de escritorio descubre los catálogos nuevos automáticamente, exige inglés, español y portugués, e informa de diferencias de claves o marcadores. La aplicación sigue las preferencias de idioma del sistema, prueba el idioma base cuando no hay traducción regional y recurre al inglés.

## Páginas y enlaces profundos

La interfaz de escritorio exporta páginas separadas del App Router para Perfiles, Contexto, Marca, Recursos, Salidas, Borradores, Generaciones y Vídeos completados. Los identificadores de los espacios de trabajo se crean en la base de datos local después de compilar la aplicación, así que una página exportada recibe el identificador como parámetro de consulta, por ejemplo `/brand?workspace=2`. La navegación de un perfil a un borrador también lleva el identificador del perfil en la URL. El diseño del estudio resuelve esos identificadores mediante Tauri.

Las ejecuciones completadas se abren en `/completed-video?workspace=<workspace-id>&run=<run-id>`. La aplicación resuelve el vídeo desde el espacio de trabajo local seleccionado, así que el enlace funciona con la base de datos de Arrumo correspondiente.

Los enlaces profundos de escritorio usan `arrumo://open/<section>?workspace=<id>`. Las páginas de perfiles y de ejecuciones también aceptan `profile=<id>` o `run=<id>`, respectivamente. Por ejemplo, `arrumo://open/generation-run?workspace=2&run=8` abre la ejecución correspondiente en la base de datos local. `arrumo://open/settings?workspace=2&section=plugins` abre Ajustes en `general`, `agent`, `services`, `plugins`, `quality` o `backup`; añade `scope=workspace` para el ámbito del espacio de trabajo, o `plugin=<id>` con `section=plugins` para abrir la página de un complemento. `arrumo://open/appearance?workspace=2` abre Ajustes del espacio de trabajo › Apariencia, que solo cambia cómo se ve el espacio de trabajo en Arrumo. `arrumo://open/drafts?workspace=2&compose=1` empieza un vídeo nuevo a partir de grabaciones, y `compose=scratch` empieza uno desde cero. Linux registra el esquema al arrancar, y las compilaciones de depuración de Windows lo registran para pruebas. El registro en paquetes instalados sigue la configuración de esquemas de escritorio de Tauri.

## Recuentos de uso e informes de errores

Los recuentos de uso anónimos y los informes de errores están activados por defecto, con interruptores en **Ajustes › General › Datos y privacidad** (`get_privacy_settings`/`set_privacy_settings` por MCP y A2A). Las versiones solo envían algo si se compilan con `ARRUMO_USAGE_KEY` (una clave de app de [Aptabase](https://aptabase.com); `ARRUMO_USAGE_ENDPOINT` cambia su API de eventos) o `ARRUMO_CRASH_DSN` (un DSN de [Sentry](https://sentry.io)). Las versiones de colaboradores no tienen ninguna de las dos y no envían nada.

- **Uso.** La app de escritorio envía con [`tauri-plugin-aptabase`](https://github.com/aptabase/tauri-plugin-aptabase), con su propio seguimiento de errores desactivado; los procesos sin interfaz de la CLI, MCP y A2A publican en la misma API. [`telemetry.rs`](https://github.com/aidevs-pt/arrumo-video-editor/blob/main/crates/workspaces/src/telemetry.rs) decide qué se envía: los eventos `app_started`, `workspace_created`, `video_queued`, `video_generated`, `media_generated`, `plugin_installed` y `backup_exported`, con propiedades que solo pueden ser indicadores, recuentos, números o identificadores de hasta 64 caracteres, más el identificador aleatorio de instalación como `install`. [Ajustes, actualizaciones y privacidad](../../user/settings.mdx) detalla las propiedades de cada evento.
- **Errores.** [`tauri-plugin-sentry`](https://github.com/getsentry/sentry-tauri) informa de los pánicos y errores de Rust e inyecta el SDK de navegador de Sentry en el webview, así que los errores de la interfaz se envían por el mismo cliente. `before_send` descarta cada informe mientras el interruptor está desactivado, quita los nombres de usuario y de equipo, las migas de pan y los datos de la petición, recorta las rutas a nombres de archivo y oculta lo que parece una ruta. No se recogen minidumps nativos. El interruptor se copia en un archivo pequeño junto a los datos, para que los informes previos a abrir la base de datos también lo respeten. El seguimiento de sesiones está desactivado.

Añade un evento con `WorkspaceStore::track_usage` solo para momentos significativos y poco frecuentes.

## Actualizaciones y versiones

Las versiones publicadas se actualizan solas con [`tauri-plugin-updater`](https://v2.tauri.app/plugin/updater/) a partir del `latest.json` de la última versión de GitHub, comprobado con la clave pública compilada desde `ARRUMO_UPDATER_PUBKEY`. Las versiones sin ella, o con `ARRUMO_STORE_BUILD`, nunca buscan actualizaciones. Los comandos de escritorio son `update_status`, `check_for_update` e `install_update` (ahora o al cerrar).

Cada inicio escribe una marca que la interfaz borra cuando lleva 30 segundos abierta. Si un inicio encuentra la marca, busca una versión más reciente antes de abrir ningún dato y la instala enseguida, así que una versión que falla al arrancar se puede sustituir con la siguiente.

Las versiones las compila el flujo **Release** que ejecuta el propietario; sus secretos y pasos están en [`docs/releasing.md`](https://github.com/aidevs-pt/arrumo-video-editor/blob/main/docs/releasing.md).
