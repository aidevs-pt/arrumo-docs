## Espacios de trabajo

Usa `create_workspace` para crear un espacio de trabajo; empieza con un icono y un color predefinidos al azar. Usa `rename_workspace` para cambiarle el nombre y `set_workspace_appearance` para cambiar su color, su icono (uno de `clapperboard`, `camera`, `mic`, `sparkles`, `rocket`, `gamepad`, `book`, `palette`, `music`, `code`, `heart`, `leaf`, `briefcase`, `graduation-cap`, `utensils`, `dumbbell`) o la imagen que se muestra en su lugar. Usa `get_workspace_context` y `set_workspace_context` para leer o reemplazar su contexto en Markdown. Usa `list_profiles`, `create_profile` y `update_profile` para gestionar los perfiles de producción; `draft_profile` para que el agente del espacio de trabajo proponga la descripción y las pautas de edición de un perfil nuevo a partir de su nombre y unas palabras sobre los vídeos (no se guarda nada); y `set_profile_description` y `set_profile_format_context` para su descripción y su contexto por formato. Usa `share_asset_with_profile`, `unshare_asset_from_profile`, `list_profile_assets` y `list_asset_profile_shares` para limitar recursos del espacio de trabajo a perfiles. Pasa el identificador de un perfil como `profile_id` en los ajustes del borrador. La cola captura el contexto y el perfil guardados cuando crea la ejecución.

## Copias de seguridad

Usa `arrumo-workspaces <database-path> snapshot-database <new-sqlite-file>` para capturar el estado confirmado de SQLite, incluidas las escrituras del WAL de origen. El comando crea un archivo nuevo e informa de su SHA-256 y su tamaño en bytes. La instantánea incluye los registros de SQLite y los ZIP de complementos almacenados. Los medios gestionados, los archivos de entrega y las credenciales del almacén del sistema necesitan pasos de copia aparte.

Para una copia completa, `export-backup <new-zip>` escribe en un solo ZIP la instantánea de la base de datos, los medios gestionados y las entregas verificadas, con un manifiesto que nombra los espacios de trabajo y los complementos instalados y lista el tamaño y el SHA-256 de cada archivo (`verify-backup <zip>` lo comprueba). Las credenciales se quedan en el almacén del sistema. `stage-backup-import <zip>` verifica una copia y la prepara junto a la base de datos; la aplicación de escritorio la aplica en su siguiente arranque, antes de que nada abra la base de datos, y guarda los datos reemplazados en una carpeta fechada `workspaces.sqlite.before-import-*` (`apply-backup-import` hace lo mismo sin interfaz; `cancel-backup-import` descarta la copia preparada). Se rechazan las copias de una versión más nueva de Arrumo. MCP y A2A exponen `export_backup`, `verify_backup`, `stage_backup_import`, `get_backup_import_status` y `cancel_backup_import`. En la aplicación está en **Ajustes › Importar y exportar**.

## Perfiles

Para crear y listar perfiles del espacio de trabajo 1:

```sh
cargo run --locked -- ./workspaces.sqlite create-profile 1 "Reviews" "## Keep hands-on demos" "#532A9D"
cargo run --locked -- ./workspaces.sqlite profiles 1
```

Para actualizar el perfil 1 del espacio de trabajo 1:

```sh
cargo run --locked -- ./workspaces.sqlite update-profile 1 1 "Tutorials" "## Explain each step" "#532A9D"
```

Pasa unas pautas vacías para borrarlas, u omite el color al actualizar para quitarlo. Al crear, las pautas y el color son opcionales. Los colores usan `#RRGGBB`.

Un perfil también tiene una descripción de una línea de hasta 280 caracteres, que se muestra en las listas, y contexto en Markdown para un formato de salida concreto. El contexto de formato solo se aplica a los formatos activados, y guardar un texto vacío lo borra. Ambos se capturan con el perfil en las instantáneas de generación.

```sh
cargo run --locked -- ./workspaces.sqlite set-profile-description 1 1 "Step-by-step tutorials"
cargo run --locked -- ./workspaces.sqlite set-profile-format-context 1 1 2 "Keep each step under 20 seconds."
```

Los recursos del espacio de trabajo se pueden compartir con un perfil entero o con uno de sus formatos. Compartir no copia el archivo. Compartir con todo el perfil sustituye lo compartido con sus formatos para ese recurso, y reemplazar el archivo de un recurso conserva lo compartido. Las ejecuciones de un perfil capturan los recursos compartidos como `profile_assets`, cada uno con su `format_id`, o null para todos los formatos.

```sh
cargo run --locked -- ./workspaces.sqlite share-asset 1 3 1        # every format of profile 1
cargo run --locked -- ./workspaces.sqlite share-asset 1 4 1 2      # only format 2
cargo run --locked -- ./workspaces.sqlite profile-assets 1 1
cargo run --locked -- ./workspaces.sqlite unshare-asset 1 4 1 2
```

## Formatos de salida y entregables

Los formatos de salida del espacio de trabajo incluyen por defecto Horizontal (1920 × 1080) y Vertical (1080 × 1920). Para el espacio de trabajo 1:

```sh
cargo run --locked -- ./workspaces.sqlite formats 1
cargo run --locked -- ./workspaces.sqlite create-format 1 '{"name":"Square","width":1080,"height":1080,"enabled":true}'
```

Usa `update-format <workspace-id> <format-id> <settings-json>` para editar o desactivar un formato, y `remove-format <workspace-id> <format-id>` para quitarlo.

Los perfiles ven los formatos activados del espacio de trabajo y pueden sustituir el ancho y el alto por separado. La lista devuelve las dimensiones resueltas y las sustituciones tal cual. Al guardar, los campos ausentes o null heredan los valores del espacio de trabajo.

```sh
cargo run --locked -- ./workspaces.sqlite profile-formats 1 1
cargo run --locked -- ./workspaces.sqlite set-profile-format 1 1 1 '{"width":1280}'
cargo run --locked -- ./workspaces.sqlite set-profile-format 1 1 1 '{}'
```

Desactivar un formato lo oculta y conserva sus sustituciones para cuando se vuelva a activar. Quitar un formato elimina sus sustituciones.

Los formatos de salida del espacio de trabajo tienen ajustes de entrega complementarios: número de miniaturas, títulos y descripciones, un interruptor de etiquetas y pautas y especificaciones de miniaturas en Markdown. El vídeo final y los subtítulos siguen siendo obligatorios. Al reemplazar los ajustes complementarios, los campos omitidos vuelven a cero, false o texto vacío.

```sh
cargo run --locked -- ./workspaces.sqlite set-format-delivery 1 1 '{"thumbnails":3,"titles":3,"descriptions":1,"tags":true}'
cargo run --locked -- ./workspaces.sqlite format-delivery 1 1
```

Los ajustes de entrega de un perfil pueden sustituir valores concretos del espacio de trabajo para cada formato activado. El comando de lectura devuelve los valores del espacio de trabajo, las sustituciones y la entrega efectiva. Guardar reemplaza el conjunto de sustituciones del perfil. Los campos omitidos y null heredan. Cero, false y el texto vacío son valores explícitos.

```sh
cargo run --locked -- ./workspaces.sqlite set-profile-delivery 1 1 1 '{"thumbnails":0,"tags":false}'
cargo run --locked -- ./workspaces.sqlite profile-delivery 1 1 1
```

Los ajustes de entrega pueden incluir `portrait_derivatives`. Para pedir dos derivados verticales a partir del perfil 1, usa `{"portrait_derivatives":{"count":2,"source":{"type":"profile","profile_id":1}}}` dentro del JSON de ajustes de entrega. El perfil de origen debe pertenecer al espacio de trabajo. Usa `{"type":"manual","guidance":"…","thumbnails_per_video":2,"thumbnail_guidance":"…"}` como origen para indicar directamente las pautas del derivado y de sus miniaturas. Un recuento de cero desactiva las peticiones de derivados. La entrega de un perfil puede sustituir la configuración vertical como un todo.

Usa `list_output_formats`, `create_output_format` y `update_output_format` para configurar las dimensiones de salida del espacio de trabajo. Usa `get_format_delivery` y `set_format_delivery` para los entregables complementarios. Enviar un reemplazo devuelve a sus valores predeterminados los campos complementarios omitidos. El vídeo final y los subtítulos siguen siendo obligatorios.

Usa `list_profile_formats` y `get_profile_delivery` para ver los ajustes de formato heredados y efectivos. Usa `set_profile_format_overrides` y `set_profile_delivery` para reemplazar las sustituciones de un formato en un perfil. Omite un campo para heredar su valor del espacio de trabajo, o envía un objeto de sustituciones vacío para heredar todos los campos de ese grupo. Cero y false explícitos siguen siendo sustituciones.

Usa `remove_output_format` con un espacio de trabajo y un identificador de formato para quitar ese formato de las ejecuciones futuras. Los ajustes de generación capturados conservan sus formatos originales.

Usa `thumbnail_reference_ids` para elegir recursos de imagen existentes en una configuración de entrega, también dentro de un origen vertical manual. Los identificadores pertenecen al espacio de trabajo. En las entregas de perfil, omite el campo de primer nivel para heredar la selección del espacio de trabajo o pasa una lista vacía para borrarla.

## Recursos

Importar un recurso al espacio de trabajo lo copia en el almacenamiento propio del espacio de trabajo, junto a la base de datos, en `<database>.media/<workspace-id>/<asset-id>`. El archivo de origen se queda donde está. Las extensiones de archivo clasifican los recursos de imagen, audio y vídeo admitidos.

```sh
cargo run --locked -- ./workspaces.sqlite import-asset 1 ./reference.png
cargo run --locked -- ./workspaces.sqlite assets 1
cargo run --locked -- ./workspaces.sqlite set-asset-notes 1 1 "Keep the product centered"
```

Usa `import_workspace_asset` con un identificador de espacio de trabajo y una ruta local absoluta en `source` para copiar un archivo multimedia en el almacenamiento gestionado. Usa `list_workspace_assets` para encontrar los identificadores de recursos para las fuentes de un borrador. Usa `generate_library_images` para crear de una a cuatro imágenes a partir de una descripción (`aspectRatio` `16:9`, `9:16`, `1:1` o `4:5`) con los proveedores de imágenes del espacio de trabajo, o con un `provider` concreto; se añaden a los recursos con las `notes` indicadas. Usa `generate_library_speech` para locutar hasta 5.000 caracteres en un recurso de audio con el primer proveedor de voz (o uno concreto) y su voz configurada. Usa `generate_library_audio` para crear música instrumental o un efecto de sonido (`kind` `music` o `sound-effect`) de `seconds` de duración a partir de una descripción en `prompt`, con el primer proveedor de ese tipo o un `provider` concreto; el proveedor fija los límites de duración y el recurso se etiqueta como Música o Efecto de sonido. La música de un plan de recursos aprobado puede ir bajo un vídeo. Usa `generate_library_video` para crear un clip (`16:9`, `9:16` o `1:1`, con `durationSeconds` dentro de los límites del modelo) con el primer proveedor de vídeo que tenga adaptador y clave; consulta al proveedor hasta su tiempo límite, y el clip se añade a los recursos con las `notes` indicadas y el modelo usado. `list_video_models` lista los modelos de cada proveedor de vídeo, el seleccionado, y las imágenes y vídeos de referencia que admite cada forma de llamarlo; pasa `provider` y `model` para elegir uno, y `references` (identificadores de recursos de imagen o MP4 del espacio de trabajo) para animarlos o seguirlos. `generate_library_images` también acepta `references` de imagen e informa de cuántas aceptó cada proveedor. Un proveedor indicado que esté desactivado se rechaza. `get_provider_usage` lee la cuota de cada proveedor con clave mediante el `usage.json` del SDK de su complemento, y la cuota del plan de cada agente instalado mediante su `usageRun` del esquema 11 (unidad `percent`, con la duración del periodo en `windowMinutes`) (uso, límite, fecha de renovación y un nivel: `ok`, `warning` con un 20 % o menos restante, `danger` con un 10 % o menos, o `unknown` con el motivo); la aplicación de escritorio lo muestra en Ajustes › Servicios y claves, como un aviso descartable en la parte superior y de nuevo encima de Generar.

Usa `replace_workspace_asset` por MCP o A2A con `workspaceId`, el `assetId` activo y una ruta local absoluta en `source` a un archivo del mismo tipo. El `asset` devuelto tiene un identificador nuevo. Usa ese identificador en las operaciones siguientes sobre el reemplazo.

Usa `describe_workspace_assets` con `workspaceId` y hasta 60 `assetIds` para que el agente del espacio escriba el contexto, el grupo y las etiquetas de cada recurso. Mira la propia imagen, un fotograma de un vídeo o la transcripción que Arrumo ya tiene de su voz, y reutiliza los grupos y etiquetas que ya existen en el espacio. Las respuestas se guardan y se devuelven en `assets` y `organization`. Los recursos que no puede mirar se devuelven en `omitted`, cada uno con un `reason`: `agent_cannot_see`, `unsupported_format` (como GIF o SVG), `nothing_to_read` (audio sin voz), `unavailable` (falta el archivo) o `not_described`. Pasa `planOnly: true` para obtener solo `eligible` y `omitted` sin consultar al agente.

Usa `remove_workspace_asset` por MCP o A2A con `workspaceId`, `assetId` y el nombre de archivo guardado exacto como `confirmedName`. Los ajustes que apuntan al recurso lo sueltan: roles de marca, referencias de miniaturas, fuentes de borradores, recursos compartidos con perfiles y organización. El recurso se conserva cuando lo necesita un vídeo que aún puede continuar (en cola, en curso, esperando revisión o fallido), un vídeo terminado o una animación. La respuesta tiene `removed` y un `result` cuyo `state` es `removed`, `missing` (no hay ningún recurso con ese ID y nombre) o `in_use`, con `uses`, que nombra cada vídeo o animación por `kind` (`open_video`, `finished_video`, `animation`) y `name`. Para quitar varios, llama a `remove_workspace_assets` con `workspaceId` y `assets`, una lista de `{assetId, confirmedName}`; responde por cada uno. Quitar un recurso deja la importación original en su sitio.

Usa `import_thumbnail_reference` (CLI `import-thumbnail-reference <workspace-id> <source-path>`) para importar una imagen local con notas de referencia para miniaturas. Usa `set_asset_notes` con el identificador del espacio de trabajo, el del recurso y notas en Markdown para cambiar las pautas de uso del recurso. Pasa una cadena vacía para borrar las notas.

Usa `set-batch-asset-notes <workspace-id> <asset-ids-json> <markdown>` en la CLI, o `set_batch_asset_notes` en MCP y A2A, para reemplazar a la vez las notas de varios recursos. Un recurso inexistente o de otro espacio de trabajo deshace toda la actualización.

Lee las etiquetas y el grupo de un recurso con `asset-organization <workspace-id> <asset-id>` o `get_asset_organization` por MCP y A2A. Reemplázalos con `set-asset-organization <workspace-id> <asset-id> <settings-json>` o `set_asset_organization`. Los ajustes contienen un `group` opcional y una lista `labels`. Un objeto de ajustes vacío borra ambos sin cambiar el recurso ni sus referencias.

Usa `replace-asset <workspace-id> <asset-id> <source-path>` para importar un reemplazo del mismo tipo. Devuelve el identificador del recurso nuevo, traslada las notas de uso y la organización, y actualiza las referencias de borradores, marca y miniaturas. El medio anterior sigue disponible para las ejecuciones que lo capturaron. Los archivos originales se quedan donde están.

Usa `remove-asset <workspace-id> <asset-id> <confirmed-name>` para quitar un recurso sin usar y su archivo gestionado. Usa el nombre de archivo guardado exacto. Las fuentes de borradores, las asignaciones de marca, las referencias de miniaturas y las referencias de ejecuciones capturadas protegen sus recursos. Si la limpieza de archivos se interrumpe, repite el mismo comando para terminarla. Al arrancar, la aplicación de escritorio reintenta las limpiezas de recursos pendientes y recupera los archivos gestionados reemplazados que ya no tienen referencias.

Herramientas de voz y doblaje: `list_speech_models` lista los modelos con nombre de cada proveedor de voz, para qué es ideal cada uno y su límite de caracteres; pasa `provider` y `model` a `generate_library_speech`. `get_speech_provider_status` indica el formato de audio, el límite y dónde está la clave de un proveedor de voz, nunca la clave. `list_audio_transforms` y `transform_audio_asset` cambian la voz de un recurso de audio o vídeo (`voice-change`, con un ID de `voice` opcional) o conservan solo la voz (`voice-isolation`). `list_dubbing_providers` y `dub_asset` doblan el habla de un recurso a uno de los códigos `language` del proveedor, esperando a que termine. Cada resultado es un recurso nuevo cuyas notas nombran el origen. `list_image_models` lista los modelos de imagen. `list_ready_plugins` lista los complementos activos con todos sus ajustes obligatorios y claves completos; los demás aún no pueden trabajar. `list_workspace_footage` lista el material de origen, `list_pending_reviews` las ejecuciones que esperan a una persona y `list_saved_run_motion` qué animaciones de una ejecución están en la biblioteca de animaciones.

## Contexto, comentarios y marca

La vista Contexto del espacio de trabajo edita las pautas de producción en Markdown. El editor ofrece una plantilla traducida hasta el primer guardado. La CLI devuelve JSON `null` para un contexto sin definir y una cadena vacía para un contexto que el usuario borró explícitamente.

```sh
cargo run --locked -- ./workspaces.sqlite set-context 1 '## Audience'
cargo run --locked -- ./workspaces.sqlite context 1
```

Las tarjetas de comentarios del agente están en el Contexto del espacio de trabajo. Una herramienta puede registrar una observación localmente con `add-feedback <workspace-id> <title> <markdown>`. Usa `feedback <workspace-id>` para listar las tarjetas y `update-feedback <workspace-id> <feedback-id> <title> <markdown>` para revisar una, y `remove-feedback <workspace-id> <feedback-id>` para borrarla. Las tarjetas también se pueden desplegar y editar en la aplicación de escritorio.

La vista Marca del espacio de trabajo guarda una paleta ordenada. Usa `brand-colors <workspace-id>` para leerla y `set-brand-colors <workspace-id> '["#532A9D","#FFFFFF"]'` para reemplazarla. Los colores usan notación hexadecimal de seis dígitos. Usa una lista vacía para borrar la paleta.

El catálogo de imágenes de marca asocia imágenes existentes del espacio de trabajo con los papeles `identity` (por ejemplo, logotipos o avatares) y `style` (referencia visual). Una imagen puede cumplir ambos papeles sin otra copia del archivo.

```sh
cargo run --locked -- ./workspaces.sqlite attach-brand-asset 1 1 identity
cargo run --locked -- ./workspaces.sqlite brand-assets 1
cargo run --locked -- ./workspaces.sqlite detach-brand-asset 1 1 identity
```

El Contexto del espacio de trabajo usa la barra de texto enriquecido de editorcn con Tiptap Markdown. Usa el interruptor de código Markdown para editar el Markdown directamente, incluida la sintaxis que la barra no ofrece. El espacio de trabajo sigue guardando Markdown.

`draft-context <workspace-id> <sources-json> [notes]` (y la herramienta `draft_workspace_context`) lee hasta ocho páginas web públicas, como el sitio o el canal del creador, y deja que el agente del espacio de trabajo redacte su contexto y sugiera perfiles. Solo se contactan direcciones públicas: cada redirección se comprueba y la conexión se fija a la dirección comprobada. Las páginas llegan al agente como datos citados, los enlaces ilegibles vuelven con un código de motivo, y no se guarda nada hasta que el creador guarda el borrador desde **Contexto**. El borrador también sugiere colores de marca, imágenes descritas y agrupadas y perfiles; cuando el complemento del agente acepta imágenes, mira hasta ocho (primero las miniaturas de vídeo) para describir lo que muestran. `import-context <workspace-id> <import-json>` (y la herramienta `import_workspace_context`) añade las sugerencias que el creador conserva, como `{"colors": [...], "images": [...], "profiles": [...]}`, descargando imágenes solo de direcciones públicas. Cada enlace que intenta se recuerda junto con si se pudo leer; `list_context_sources` los lista y `forget_context_source` olvida uno, y la página Contexto los muestra como fichas con la fecha de la última lectura.

Usa `list_workspace_feedback`, `add_workspace_feedback`, `update_workspace_feedback` y `remove_workspace_feedback` para gestionar las tarjetas de pautas del espacio de trabajo. Usa `get_brand_colors` y `set_brand_colors` para leer o reemplazar la paleta; `get_brand_colors` también devuelve `palette`, con el nombre de cada color y si los vídeos lo usan, y `set_brand_color_details` cambia esos datos. La generación solo lee los colores que usan los vídeos. Las ejecuciones nuevas capturan ambas entradas.

`get_brand_fonts`, `import_brand_font` (un .ttf u .otf estático en una ruta absoluta, como fuente `heading` o `body` en `regular` o `bold`) y `remove_brand_font` gestionan las fuentes de marca. Al importar se comprueban las letras con tilde y los símbolos comunes, y se mide el ancho medio de las letras para que el texto de las animaciones se ajuste. Los archivos se guardan por SHA-256 y las ejecuciones registran las fuentes en su instantánea, así que los nuevos renderizados conservan las fuentes con las que empezó la ejecución. La CLI tiene `brand-fonts`, `import-brand-font` y `remove-brand-font`.

Usa `list_brand_assets`, `attach_brand_asset` y `detach_brand_asset` por MCP o A2A para gestionar qué imágenes del espacio de trabajo sirven de recursos de identidad o de referencias de estilo. Quitar un papel conserva la imagen en la biblioteca del espacio de trabajo.
